# 独立 Addon 边界

Gameplay 拥有能力服务端逻辑、客户端控制与 HUD、交互 Mixin、进度及语言资源。外观资源、编辑器、渲染与外观同步代码留在主仓库；不在 Addon 嵌入外观 Mod 或 API 类。

客户端仅通过 `top.csituka.magicaland.api` 的公开契约对接外观：只读外观查询、可撤回的手持隐藏/注视覆盖及视觉入口。不得直接访问配置对象、缓存、骨骼或合成状态。

服务端继续判定授权、距离、遮挡、碰撞、真实工具槽位、库存、死亡、交互权限和伤害；捏脸信息不能作为能力授权。

两个 Mod 独立版本，用明确 Maven 发布物对接。可以在同一 IDE 中打开，但不能恢复跨仓源码依赖。API 运行实现只随外观 JAR 提供一次。

目前两端仍需兼容外观与 Gameplay，不扩大为“无外观独立运行”或“原版客户端可进玩法服务器”。同步服务端仍在外观 JAR。

来源：原仓库保全 `d4786bd`，初始导入 `d6166f3`；保留作者、MIT 许可和全部未提交远控源码，早期历史在 [Magical-Land](https://github.com/Magical-Land-Official/Magical-Land)。

禁止因拆仓更改模组 ID、进度/条件 ID、`magicaland_remote_cargo` 和 NBT 字段、远控通道/实体 ID、授权标签。

## 迁移验证（2026-09-10）

全部 26 个 Gameplay 生产 Java 源码在真实 Minecraft/Fabric 依赖下，仅使用公开 API 类组成的临时开发命名空间测试 JAR 编译通过；编译 classpath 不包含外观内部实现。架构 169 项、远控结构 77 项检查通过，Gameplay 公共/服务端代码与原快照保持一致。

方向/飞行、彩蛋状态/顺序/食物、携带槽共 5 项无窗口回归通过，合计 727,810 条检查。使用当前源码、真实外观 0.3.0/Gameplay 0.1.0 元数据及 Fabric 类加载器的隔离夹具，验证了 18 个 Mixin 目标转换；没有进入游戏主循环，不等于正式发布 JAR 的重映射或游戏效果验收。

Gradle 文件通过语法检查。真正的 Gameplay 依赖解析需要先发布外观 `0.3.0` 的主 Mod 和 API 开发产物；本轮未自行完整构建、发布或启动游戏，因此独立 Maven 消费和实机表现仍需后续验收。不能用结构检查或临时测试 JAR 冒充正式发布产物验证。
