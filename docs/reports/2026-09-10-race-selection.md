# 种族系统检查记录

日期：2026-09-10。版本：Gameplay 0.3.0、Appearance 0.3.4 / API 1.4。

## 本轮内容

- 首次选择独角兽、天马或陆马；身份随世界和玩家 UUID 保存。
- 三种改族药水，先由创造栏和管理员提供。
- 玩法设置中管理改族方式、开放种族与角翅外观限制。
- 服务端检查身份、权限、规则版本及安全状态；念力出窍接入独角兽身份。
- 外观包提供临时角翅覆盖与变身光尘接口，保留原外观预设。

使用说明见[种族选择](../races.md)。

## 独立检查

两个仓库使用实际 Minecraft/Fabric 依赖进行 Java 17 目标的源码类型检查。Gameplay 编译只依赖外观公共 API 文件，不包含外观内部实现。

结果通过：Gameplay 64 个源码、Appearance 145 个源码；种族规则 7,864 项、消息 1,935 项、存档 37 项、接入结构 107 项；界面行为 452 项、双语布局 165 项。外观副本隔离 158 项、API 132 项及两仓架构检查也通过。

回归范围：

- 选择规则、药水／自由／锁定模式、管理员例外、种族开放范围及规则版本冲突。
- 真实 NBT 文件保存与重读、未知种族和扩展字段保留、损坏数据隔离。
- 消息编解码、长度与数量限制、截断、重复条目、非法标识及操作回执。
- 界面确认／取消、只读权限、草稿冲突、超时重试、断线及旧回执隔离。
- 双语文案、占位符与小窗口的保守换行检查。
- 外观副本隔离、覆盖注册与撤销、API 兼容及两仓职责边界。

独立审查发现并修复了一个多人提示问题：其他玩家的状态广播原本可能被误当成当前操作失败。现在选择和保存规则携带独立请求编号，拒绝提示只处理对应回执。

种族核心、设置与界面回归的源码和入口现由作者在本地维护。其中服务端接入检查使用源码断言，界面行为检查使用控件桩；真实文件和消息测试使用 Minecraft 的 NBT 与缓冲区实现。

## 待实机验收

本轮未运行 Gradle 构建或启动游戏。以上检查通过后，仍需验收：

1. 原世界首次选择、关闭后从轮盘再次进入，以及已选择玩家重连时不再提示。
2. 三族在世界、背包和捏脸中的角翅显示；更换预设不会改族，退出 Gameplay 世界后原预设恢复。
3. 生存喝完才改族并返还玻璃瓶；中途停止、起跳、受伤或规则不允许时保留药水；创造模式不消耗。
4. 普通玩家只能查看规则；管理员保存后，其他玩家的显示与选项同步更新。
5. 自由改族、仅管理员改族、禁用某族和外观混搭；能力始终按种族授权。
6. 死亡、跨维度、重连后的身份；管理员改族时结束出窍并安全结算携带物品。
7. 多人同时操作及网络延迟下的回执、变身光尘与音量。

天马和陆马本轮开放身份及对应外观，生存能力另行开发；改族药水的生存获取方式也留待后续确定。
