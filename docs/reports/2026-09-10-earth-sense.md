# 基础震动感知检查记录

版本：Gameplay 0.3.1，依赖 Appearance 0.3.4 / API 1.4。

## 本轮实现

用户决定先制作陆马震动感知，后踢和范围砸地等补充攻击动画后继续。

已接入 14 格地面活动感知、四类方向信号、距离强弱与活动脉冲、灰白滤镜及强度设置。轮盘按当前种族显示念力出窍或震动感知，按键保持 R 选择、V 开关。详细规则见[使用说明](../earth-sense.md)。

本轮代码修改集中在 Gameplay；外观包继续通过上一轮的种族显示接口配合，没有新增模型或攻击动画。矿物探测、生物轮廓、自然共鸣、消耗和成长未加入本版。

## 验证范围

- 使用真实 Minecraft/Fabric 依赖，对 Gameplay 全部 76 个生产源码进行 Java 17 目标的类型检查，编译仅使用外观公共 API。
- 服务端核心回归覆盖方位、强弱、节奏、租约到期、关闭后迟到输入、消息边界以及有限地面连通搜索；共 148,722 项通过。
- 客户端回归覆盖请求和状态次序、维度变化、取消后迟到开始、离地衰减、失联结束，以及两种能力的选择与停止顺序。
- 修正轮盘后，重新通过会话 289 项、能力映射与改族 184 项、轮盘接入 29 项检查；其中包含不按施放键直接快速改族、再切回原种族的情况。
- 设置回归覆盖滤镜保存、无效值、失败保留、旧配置兼容，以及中英文小窗口布局。
- 独立隐藏 OpenGL 上下文使用实际滤镜和着色器，检查去饱和、透明度、深度、状态恢复、尺寸变化及错误降级；没有操作正在运行的 Minecraft 窗口。
- 读取实际 1.20.1 渲染方法字节码，检查滤镜接入位置处于世界和原版后处理之后、界面之前。模块架构、原出窍接入与种族系统回归也已复跑。

源码接入断言不等同于真实服务端行为测试，控件桩和保守字宽检查也不代替游戏内绘制。独立 GPU 测试验证的是滤镜本身，完整游戏渲染组合仍需验收。

服务端与渲染、客户端会话和设置回归的源码与入口现由作者在本地维护。

## 已修正的问题

- 离地后重新接地时，非采样帧不再发送空的已接地结果，避免方向提示短暂闪空。
- 设置保存失败时，用错误提示替换原说明，避免与新增滤镜按钮及原说明重叠。
- 种族选择页同步更新陆马能力说明，避免仍显示“能力规划中”。
- 根据种族筛选轮盘内容，修正切为陆马后仍显示独角兽能力的问题。可见位置与能力编号分开处理，陆马的第一项正确对应震动感知。
- 收到改族同步时清除旧能力选择和悬停；快速切回原种族不会恢复旧选择，同种族的普通同步不影响选择。
- 滤镜异常时保留方向提示，并提供降级提示；缩放、资源重载与断线有对应清理。

## 待实机验收

1. 独角兽轮盘只显示念力出窍，陆马只显示震动感知，天马显示暂无能力；快速改族后旧选择不能直接施放，重新选择后能力正常。
2. 敌对、中立、友善生物和玩家的分类；静止、潜行、步行、奔跑和落地节奏。
3. 四周及背后的方向，第一／第三人称转向与抬头低头时的稳定性。
4. 平地、墙基、半砖、楼梯、木桥、深沟和悬空平台的信号；拥挤区域及 14 格边缘可能出现保守漏报。
5. 短暂离地、长时间离地、入水、死亡、改族、换维度、失焦和重连后的清理。
6. 滤镜三档、夜间亮度、窗口缩放、资源重载，以及光影模组降级提示。
7. 多人同时开启时的延迟、服务器负载和活动人数上限。

## 当前测试游戏

开发期间先构建并启动了上一轮种族测试快照：Appearance `0.3.4+race-test-20260910` 与 Gameplay `0.3.0`。用户在该版本发现改族后轮盘仍显示独角兽能力，随后要求修复并重启。

修复后的 Gameplay `0.3.1` 已完成真实 Gradle 构建，并于 2026-09-10 21:05（英国当地时间）启动，包含震动感知和按种族筛选的轮盘。外观沿用同一测试依赖，没有重编或修改。旧游戏正常退出后备份存档、配置与音量设置，新版使用原测试世界和玩家身份。

启动日志已完成资源和音频初始化。没有操作游戏画面；轮盘和震动感知的实际使用效果仍由用户验收。本轮没有提交或推送。
