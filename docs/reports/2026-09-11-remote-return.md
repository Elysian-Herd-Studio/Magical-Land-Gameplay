# 念力出窍：携物回航

日期：2026-09-11。记录携物回航接入时的检查，该阶段未修改主模组。随后已构建包含回航和试玩修复的测试版；当前状态见[念力出窍](../remote-presence.md)。

## 本轮变化

- 退出后先恢复本体视角。整个携带栏为空时光团直接消失；有货时等待 6 tick，再开始飞返。
- 光团追随本体当前位置，利用直达路线、来路记录和分批搜索绕障。正常堵路时等待重试，不穿墙，也不因超时直接交货。
- 回航期间本体可以移动、转头、切槽或打开背包。光团停止交互和拾物，到货前不能再次发动出窍。
- 抵达附近且最后一段路可通行时交付。原带出的物品优先尝试原槽，再补兼容堆叠和空槽，余量落在本体脚边；保留名称、附魔、耐久和全部 NBT。
- 回航显示沿用物品朝向与惯性，并带较小的光焰。选中槽为空但其他槽有货时，仍会展示携带物。解除本体注视，角光保持到光团消失。
- 客户端退出会话不再清空所有实体的持物动画，避免回航时重播掏出动作；实体移除、离开世界或断线时回收对应状态。

## 货物与异常恢复

货物始终保存在 `magicaland_remote_cargo` 的玩家 UUID 库存中，实体只携带显示副本。手动控制、回航和待交付分别管理，重复停止消息、本体操作包和迟到输入不会重复启动或结算回航。

正常堵路只暂停飞行。死亡、掉线、换维度、权限失效、异常卸载或意外离本体过远时，才结束实体并通过持久库存处理剩余货物；重新上线后可恢复待交付内容。死亡继续遵守 `keepInventory` 和消失诅咒规则。

背包接收或脚边掉落未能完成的部分留在库存，稍后重试。玩家背包与世界数据仍分别保存，断电或单独回滚存档不具备跨文件事务保证；已有的一致备份要求不变。

## 检查范围

118 个 Gameplay 源文件通过仅依赖外观公共 API 的 Java 17 类型检查。实际 Fabric 类变换检查通过，保留了上一轮精神回声的渲染挂钩。

独立回归已通过：包括货物结算、拾取、碰撞、寻路、回航运动和服务端实现边界。客户端检查了成熟持物姿态、回航期间禁止预测动作、选中空槽的携货显示、缓存保留与清理，并重跑原有视角、工具朝向及瞄准数学检查。仓库架构与远控边界检查也已通过。

回航相关检查入口：

- `tests/remote/RemoteReturnNavigatorTest.java`：来路、绕障、移动目标及有限寻路预算。
- `tests/remote/RemoteReturnMotionTest.java`：回航加减速、转向和抵近移动。
- `tests/remote/RemoteReturnIntegrationTest.java`：碰撞、回航状态、交付与异常恢复的实现边界。
- `tests/remote/RemoteCargoInventoryTest.java`：归还顺序、满包余量、NBT 和数量守恒。
- `tests/remote-client/run-tests.ps1`：实际持物动画配合测试实体，以及客户端与渲染边界检查。

这些检查未运行 Minecraft 主循环或读取玩家存档；独立检查阶段尚未构建、启动或推送。

当时未覆盖空货与选中空槽的退出表现、回航期间本体操作、绕障等待与恢复、满包余量及不同 NBT 物品守恒的实机表现。死亡、重连、换维度与区块卸载后的货物恢复，以及多人持物朝向、惯性、角光、本体注视和复杂环境寻路也未记录实测结果。

当前完整规则见[念力出窍](../remote-presence.md#携物回航)。
